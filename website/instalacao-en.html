Installation

Installing, step by step

Packages for every system are on the releases page; the newest one is at the top. The security warnings below are expected. They do not mean anything is wrong, and they only appear the first time.

Windows

  1. Download aquorbium-<version>-win64.exe.
  2. Open it. Windows shows a blue "Windows protected your PC" box: click "More info", then "Run anyway".
  3. If Windows asks for administrator permission, click "Yes".
  4. Click "Next" to the end. The last page has "Run Aquorbium" already ticked. Aquorbium is then in the Start menu and on the desktop.

Without installing: unzip aquorbium-<version>-win64.zip and open Aquorbium.exe.

macOS

  1. Download aquorbium-<version>-Darwin.dmg. It works on Intel and on Apple Silicon Macs.
  2. Open it and drag Aquorbium into Applications.
  3. Open it. The first time, macOS blocks the app with a message saying that Apple could not confirm it is free of malicious software. You may see "cannot verify the developer" or "is damaged and can't be opened" instead. In every case:
    • This is not a defect or a virus: the app is signed ad hoc, without a paid Apple Developer ID.
    • Click "OK" or "Done", not "Move to Trash".
  4. Allow the app, once, in one of two ways:
    • In System Settings: go to Privacy & Security, scroll to the security section, click "Open Anyway", confirm with your password or Touch ID, and click "Open". On macOS 14 or earlier: right-click the app in Finder → Open → Open.
    • In Terminal, if the button does not appear:
xattr -dr com.apple.quarantine "/Applications/Aquorbium.app"

If nothing is printed, it worked. The command only removes the "quarantine mark" macOS puts on every downloaded file.

Linux

  • Ubuntu 22.04+, Debian 12+, Mint 21+: double-click the .deb, or run sudo apt install ./aquorbium-<version>-Linux.deb.
  • Fedora, Arch, openSUSE and other distributions:
    • AppImage: make it executable (Properties → allow executing, or chmod +x) and open it.
    • .tar.gz: unpack it and run ./install.sh. It installs for your user only, without root, and ./install.sh --remove undoes it.

The first time you open it

  1. Every opening is another piece. The session's seed proposes a biome - the water, the light, the population, the bodies, which modules wake - and a world of keys, harmony and form. With VARY on (bottom strip) the controls also move slowly by themselves. Play from there.
  2. The TUTORIAL button explains the instrument step by step, and LEARN explains any control you point at, in English, Portuguese, French or Spanish (the language button: EN/PT/FR/ES).
  3. AUDIO chooses the output device. HEADPHONES places each organism around your head: use it with headphones only.
  4. The microphone (the ROOM) stays off until you turn it on.

Troubleshooting

Windows: "Windows protected your PC". Click "More info", then "Run anyway". If an antivirus moves Aquorbium.exe to quarantine, restore it and allow it: the program is built by the public continuous integration of this repository, from this source code.

macOS: "damaged", "cannot verify the developer" or "Apple could not confirm". Follow step 4 of macOS: Open Anyway in Privacy & Security, or the xattr command in Terminal.

Linux: the window never opens. Install the .deb with apt, which also installs the dependencies. With the AppImage or the .tar.gz, the system needs ALSA, FreeType, Fontconfig, X11 and GLib, which any desktop has. If the AppImage does not open, install libfuse2 (Ubuntu 22.04+: sudo apt install libfuse2), or start it with ./aquorbium-<version>-linux-x86_64.AppImage --appimage-extract-and-run.

No sound. Click AUDIO and choose the output. Also check the OUTPUT TRIM in the header and that MUTE and PAUSE are off.

Clicks or dropouts. In AUDIO, choose a buffer of 512 samples. On Linux the audio thread asks for real-time priority; the status line shows RT 70 when it gets it and RT no when it does not. To allow it, add your user to the audio or pipewire group (depending on the distribution) and restart the computer. Heavy programs running beside the Aquorbium (compilers, video) also cause dropouts.

Anything else: write to rasgo.instruments@gmail.com with your system and version, what you did, and the message you saw. You can also open an issue.

Requirements

WindowsWindows 10 or 11, 64-bit
macOS10.15 or later; Intel and Apple Silicon (Universal 2)
Linuxx86-64 with glibc 2.35 or newer (2022+ distributions)
Processor64-bit, two cores or more. Measured on an Intel Core i5-6500 (2015, 4 cores) at 48 kHz with 512-sample blocks: the audio uses about 7 % of each block's time (at most 9 %)
Memoryabout 55 MB while playing (measured)
Diskabout 15 MB
Audioany output; a microphone only for the ROOM

The processor figure was measured on the author's machine. Weaker machines have not been tested.

Building from source

git clone https://github.com/lucioaraujo/aquorbium.git
git clone --branch 9.0.3 https://github.com/juce-framework/JUCE.git
cmake -S aquorbium -B aquorbium/build -DCMAKE_BUILD_TYPE=Release -DAQUORBIUM_JUCE_PATH=$PWD/JUCE
cmake --build aquorbium/build --parallel 2
(cd aquorbium/build && ctest -LE slow --output-on-failure)

On Linux, the JUCE build needs the ALSA, FreeType, Fontconfig, X11 and GTK development packages. The workflow .github/workflows/package.yml lists them.

Status

Version 0.1.0 is the first public version. The Windows and macOS packages are built, tested and checked by continuous integration: no dependency on the Visual C++ Redistributable, and a sealed Universal 2 bundle on macOS. They have not yet been opened by the author on real Windows and Mac machines.
